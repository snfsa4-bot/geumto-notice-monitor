## 확인 완료

- 첨부 CODEX_HANDOFF.md와 README.md 검토.
- 공공데이터포털 공식 8종 페이지의 Swagger 확보: config/api-contracts.json.
- 나라장터 입찰 서비스 버전 주소, LH operation 이름, 계약 조회 날짜 인자 수정.
- 응답 결과코드 누락, 알 수 없는 응답, 페이지 반복, 전체 건수 불일치는 성공으로 취급하지 않음.
- XML 및 JSON의 실제 게이트웨이 오류 결과코드 처리.
- 최초확인 시각과 변경확인 시각, 금액 종류, 개찰과 낙찰 단계 구분.
- 상세·변경 이력 페이지, 일일 재조회 기록, 지역·단계·확인기간 필터.
- 정기 실행 시간은 UTC 00:00 = 한국시간 09:00. 예약 실행 지연 가능.
- API 실패에도 조회 현황 페이지를 렌더링·발행한 뒤 workflow 자체는 실패로 표시하도록 수정.
- 운영 정기 실행은 repository variable MONITOR_ENABLED=true 설정 전 비활성.

## 실제 API 호출 관찰

사용자가 전달한 키를 로컬 프로세스 메모리에서만 사용하여 최근 7일 기간의 소량 조회를 시험했습니다.
나라장터 15개 operation과 LH 4개 operation에서 정상 데이터 응답을 확보하지 못했습니다.
관찰된 응답은 주로 HTTP 400 / API 코드 10(INVALID_REQUEST_PARAMETER_ERROR),
일부 HTTP 500 / API 코드 01(APPLICATION_ERROR)였습니다.
이 결과로는 인증 승인 상태, 공급기관 장애 여부, 실제 공고 건수를 확정할 수 없습니다.

LH 입찰 날짜의 YYYYMMDD 형식과 발주계획 YYYYMM 형식은 공식 페이지 예제와 대조했습니다.
날짜 구분자를 추가한 변형 요청도 정상 응답을 확보하지 못했습니다.
LH 계약 API는 공식 Swagger에서 bidNum을 필수로 표시합니다.
계약번호 없이 기간 전체조회가 가능한지 실검증하기 전에는 전체 계약수집 성공을 선언하지 않습니다.

2. 정상 응답을 확보하고 7일 전체 페이지 수집 후 공식 원문과 공고번호·제목·금액 대조.
3. 교차 출처 중복공고 식별·단계 연계의 실자료 검증 및 구현 보완.
4. 지역 연관성이 약한 자료의 관리자 검토 대기 기능.
5. 공개 홈페이지의 브라우저·모바일 검증. 현재 연결된 관리형 환경에는 브라우저 조작 도구가 제공되지 않아 수행 전.
6. GitHub 저장소 업로드, 보안키 등록, Pages 배포와 HTTP 접근 확인.
7. 수동 workflow 시험 및 정상 수집 확인 후 MONITOR_ENABLED=true로 정기 운영 활성화.
