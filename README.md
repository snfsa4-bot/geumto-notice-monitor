# 성남금토 공고 모니터링 홈페이지 (Codex 전달용 시작 프로젝트)

이 프로젝트는 **기존 성남금토 홈페이지와 완전히 별개**로 사용할 공공조달 모니터링 사이트의 초기 구현입니다.

- **보여주는 화면:** 최신 공고, 지역별 필터(A-4BL·금토2·기반시설), 검색, 날짜별 게시글, 원문, 수집 성공/실패 상태
- **목표 운영:** 매일 오전 9시(KST) 수집 → 전날과 비교 → 변경 내용과 신규 내용 기록 → 홈페이지 자동 게시
- **데이터 범위:** 나라장터 사전규격·입찰·낙찰·계약 / LH 발주계획·입찰·개찰·계약
- **보조 정보:** LH 기술혁신파트너몰, 국토교통부, 환경영향평가(EIASS)는 공식 API 또는 공개 게시판의 합법적 조회 방식 검증 후 2단계 연결

> 현재 단계: **사이트 UI 및 데이터 흐름 시작 코드**입니다. 공공데이터 인증키가 없고 API별 파라미터 검증이 완료되지 않았으므로, 실제 공고 자동수집·실서비스 배포를 완료한 상태가 아닙니다. Codex가 `CODEX_HANDOFF.md`의 체크리스트를 먼저 수행해야 합니다. 화면은 검증되지 않은 공고를 예시로 보여주지 않습니다.

## 비개발자용 가장 쉬운 순서

1. 이 폴더를 Codex 작업 공간에 넣습니다.
2. `CODEX_HANDOFF.md` 내용을 Codex에 붙여넣고 **이 프로젝트를 완성하고 실제로 배포**하도록 요청합니다.
3. [공공데이터포털](https://www.data.go.kr/)에서 나라장터 4개 + LH 4개 서비스를 활용 신청합니다.
4. 발급된 디코딩 인증키를 **GitHub 저장소 Settings → Secrets and variables → Actions → New repository secret**에서 `DATA_GO_KR_KEY`로 등록합니다. 채팅이나 코드에 붙이지 않습니다.
5. Codex와 함께 GitHub Pages 설정에서 `Source: GitHub Actions`를 선택합니다.
6. GitHub Actions의 **Run workflow**로 수동시험을 먼저 실시하고, 8개 서비스가 모두 정상인지 확인한 뒤 일일 자동실행을 켭니다.

## 컴퓨터에서 화면 미리 보기

```bash
python -m app.render
python -m http.server 8000 -d site
```

브라우저에서 `http://localhost:8000`에 접속하면 됩니다. 현재 공고는 빈 목록이 정상입니다.

## GitHub 배포에 관한 참고

현재 워크플로는 오전 9시 KST에 실행 예약하고 사이트를 직접 GitHub Pages로 배포하도록 설계했습니다. **GitHub Actions의 예약 실행은 지연·누락될 수 있어 실제 09:00 정각 게시를 보장하지 않습니다.** 정확한 시각과 실패 자동 재시도·경보까지 필요하면 Codex에서 외부 스케줄러/Cloudflare 등으로 보완해야 합니다.

## 보안·정확성 원칙

- API 키를 브라우저 코드, 정적 JSON 파일, Git 저장소에 넣지 않습니다.
- 아무 소스도 조회하지 못한 날에는 "신규 공고 없음"으로 표기하지 않고 **"조회 불완전"**으로 표시합니다.
- 개찰 1순위 ≠ 최종 낙찰, 낙찰 ≠ 계약체결. 단계를 구분합니다.
- A-4BL과 타 지구의 A-4BL을 혼동하지 않습니다.
- 공개 URL이 없는 경우 임의의 상세 페이지 링크를 만들어 내지 않습니다.
- 최초 운영 시 과거 7일을 데이터 검증한 뒤 수집을 시작합니다.
